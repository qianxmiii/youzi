# 更新记录维护规范

本规范适用于 `youzi_v2/CHANGELOG.md` 和 `youzi_v2/docs/changelog/` 下的历史归档。Codex 入口为根目录 `AGENTS.md`，Cursor 入口为 `.cursor/rules/youzi-v2-docs.mdc`；两处引用本文件，避免维护多份不同规则。

## 记录范围

- 记录已完成、用户可感知的新增功能、行为变化、重要修复及功能移除。
- 必须保留升级所需的数据库迁移、配置调整、依赖变化、兼容性影响和人工操作。必要时保留命令或配置键，并链接详细说明。
- 纯内部重构、测试补充、文档勘误、字号、颜色、间距和图标微调，若不影响使用或升级，不单独增加更新条目。检查相关文档是否过期即可。
- 不把计划、尚未验证的效果或开发过程写成已完成结果；不为文档整理本身新增一条更新日志。

## 写法

- 以项目本地日期（Asia/Shanghai）记录实际变更，日期倒序；同一天只出现一个日期标题，不推断或修改历史日期。
- 按需使用“新增、优化、修复、移除、升级说明”，同一天每类只出现一次，无内容的类别不写。
- 同一天同一功能的多次调整合并为一条；不同日期保留有意义的演进，不把后续行为提前写入历史。
- 每条原则上一句话，说明功能与结果；每个日期通常控制在 3—8 条，重要升级说明可例外。少量变化无需凑数。
- API 路径、参数清单、数据库字段、实现过程放入对应技术文档；主记录只保留必要说明及链接，不重复整段文档。
- 不记录真实客户资料、运单号、密钥、Token、Cookie、内部地址、实际报价、成本、账单或具体调价幅度。价格维护仅写“更新渠道报价配置”。示例使用明确的虚构数据或占位符。

## 归档

- 主文件保留当前自然月及此前两个自然月的记录。按发生月份判断，不按文件行数截断。
- 较早内容精简后归入 `docs/changelog/YYYY.md`，按年份链接；归档内部仍按日期倒序。
- 主文件和文档中心必须提供有效归档链接，归档必须提供返回主文件的链接。避免同一日期在主文件和归档重复。
- 归档也遵循去重和敏感信息约束，不原样搬运冗长记录；保留重要历史功能、迁移、依赖与配置要求。纯视觉调整可合并概述。
- 历史记录不是当前操作手册；涉及已被后续变更替代的历史行为时应注明，当前用法链接至业务、部署或 API 文档。

## 任务收尾

1. 判断本次变化是否需要用户更新记录，避免“每改一行代码就加一条”。
2. 合并同日同功能的现有条目，检查日期、分类与链接。
3. 检查升级操作是否保留，业务细节是否放到了正确的技术文档。
4. 扫描本次文档是否含真实业务数据和凭据；通过后才进入仓库规定的提交审核流程。

## 示例

```markdown
## YYYY-MM-DD

### 新增

- 客户管理支持按当前筛选导出 Excel。

### 修复

- 修复新建运单未出现在港前列表的问题。

### 升级说明

- 启动时执行状态迁移；部署前备份数据库，操作步骤见部署说明。
```

示例仅说明格式，不能据此声称实际代码包含对应操作。
