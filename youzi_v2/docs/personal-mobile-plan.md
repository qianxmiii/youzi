## 阶段 1：备份与恢复

已执行真实数据库备份：`youzi_v2/data/backups/youzi_v2-20261018-145035-53c2c6b4.db`。
备份完整性检查及内存恢复校验通过，共 42 张业务表；原数据库未替换，备份路径已确认被 Git 忽略。尚未执行应用实际切库或异盘备份。

在仓库根目录 PowerShell 执行：

```powershell
python youzi_v2/scripts/backup_db.py backup
```

默认读取 `youzi_v2/data/youzi_v2.db`，输出至 `youzi_v2/data/backups/`。该目录被 Git 忽略，不由静态服务公开。可用 `--backup-dir` 指定其他获准的本地目录，避免自动同步至个人网盘。此默认位置是本机恢复副本，无法防止整块硬盘损坏；异盘备份待确认获准的存储位置后再安排。

脚本使用 SQLite backup API，可包含已提交的 WAL 数据；不导入应用、不启动同步、不输出业务记录、不覆盖已有文件。它只备份数据库，不备份配置密钥、附件及日志。

将输出的备份完整路径带入以下命令，验证完整性并在内存中演练恢复：

```powershell
python youzi_v2/scripts/backup_db.py verify "实际备份文件完整路径"
```

如需生成可检查的恢复副本：

```powershell
python youzi_v2/scripts/backup_db.py restore "实际备份文件完整路径" --output "youzi_v2/data/restore-check.db"
```

目标必须不存在，也不能遗留同名 WAL/SHM/journal 文件。恢复副本不会切换应用使用的数据库；不要启动应用指向该副本，否则同步任务可能修改副本。

正式恢复步骤：先停止后端及全部同步脚本，保留原库与相关文件，再确认恢复副本完整性、业务记录及配置路径，最后经明确确认进行切换。不要在程序运行时覆盖数据库，也不要擅自删除 WAL/SHM 文件。

失败时不要把可能留下的未完成目标当作有效备份。保留错误信息；不反复重用该目标路径，不自动删除旧备份。
