# 预计送仓与 DW 窗口

## 使用

1. 在“后台管理 → 码表 → 渠道”中点击该行“时效”列或操作中的“时效”，配置离港至送仓的最短、最长天数，例如25—35天；另有“到港后送仓”区间，默认7—15天，可按渠道调整（允许0天）。渠道列表显示全程区间。
2. 在港前或在途运单列表选择一票，打开“复制 → DW窗口设置”。
3. 选择自动、普通日期范围或 Amazon 周窗口。人工确认日期可留空；填入时两项必须同时存在，优先于自动计算，普通模式保持原样，Amazon人工日期必须为同一周周日至周六。
4. “预览”只计算；“保存设置”保存这票的模式和人工日期。清空两个人工日期并保存，可恢复自动预测。
5. 列表勾选一票或多票，使用“复制DW”：每票先写现有运单明细，下一行写 `MM/DD - MM/DD`，票间空一行；跨年仍只含月日，详情保留完整年份。设置入口仍限单票。批量读取最多4个请求并发，输出顺序与勾选结果一致；缺少数据、过期、运输异常或读取失败时整批暂不复制，并列出需核对运单，不静默跳过。

复制示意（虚构运单，仅说明格式；实际明细沿用现有格式）：

```text
TEST-001 = TEST-WH = 3ctns
12/01 - 12/22

TEST-002 = TEST-WH = 5ctns
12/28 - 01/03
```

弹窗内的“复制DW”使用相同格式；预览区域仍单独展示日期范围。

## 首版计算规则

- 仅使用启用的 ATD 全程时效规则；同渠道同承运商优先，否则使用同渠道通用规则。没有唯一匹配规则时不猜测。
- 普通范围 = ATD + 最短天数，至 ATD + 最长天数；没有 ATD 时用 ETD，显示初步预计。离港日期缺失时仍可根据到港日期计算。
- 到港估算优先使用ATA，无ATA时才使用ETA，加上到港后最短/最长天数。全程估算与到港估算都有时，起止日期分别取较晚值；仅有一种估算时使用该估算，都缺失时不生成。
- 全程最短、最长均为正整数，最短不能超过最长；旧单值兼容为相同上下限。原DW提前/延后字段仅为兼容保留，计算不再应用，避免叠加扩展。
- 自动模式仅当 `addressType=AMZ` 时使用 Amazon 周窗口，WFS、3PL和未知类型保留普通范围。单票可以显式覆盖模式。
- Amazon 自动窗口固定为最晚预计送仓日期（渠道时效上限）所在的单个周日—周六，始终只有七天，不覆盖多周。Amazon人工窗口也只允许同一周的周日至周六；原有不符合的人工窗口不会静默改写，需重新确认或切换普通模式。
- 已签收且没有人工确认窗口时停止预测；已保存人工窗口可作为历史确认值查看。已取消不生成可复制窗口。
- 到港后按实际到港日期和配置的到港后区间重新估算；历史参考独立展示，不自动替换配置窗口。异常和过期只提示，不自动把日期向后滚动。

## 日期与业务边界

现有运单日期通常没有明确时区，首版采用记录中的业务日期，不擅自推断时区或做 UTC 换算。界面始终提示此限制；人工确认窗口应填写目的地当地日期。自动窗口仅为运输参考，不表示已确认预约、Amazon接收或上架日期。

人工窗口与运单原 `expected_delivery_time` 独立存储；自动查询和DW设置不改动它。渠道时效区间的上限作为SLA预警期限，预警提前提醒和严重超时天数仍按既有规则计算。只保存最新设置，尚无“已回复客户”快照或窗口历史，不应把一次复制当作客户承诺记录。

## 升级与验证

重启后端自动向渠道规则增加区间下限，旧天数作为上限并回填相同下限，无需业务回填；已有单票人工DW继续保留；到港后区间新增列默认7—15天，已有手动配置不会在后续启动被覆盖。升级前按既有流程备份数据库。见[数据库说明](./database.md)和[API说明](./api.md)。

本轮使用内存SQLite验证迁移与设置读写，合成日期验证跨周、跨年、人工优先、规则匹配及缺失数据。真实业务数据与历史预测不作为测试输入。

## 历史时效参考

签收时间已确认为实际送达目的仓。DW设置弹窗独立加载历史参考，列表批量复制不额外扫描历史。

- 全程 = 签收日期 − ATD；到港后 = 签收日期 − ATA，按记录中的自然日计算。不使用ETA/ETD作为历史实际时效起点。
- 默认读取近90天已签收数据，排除本票、未来签收、取消单和日期倒置记录；不返回单票客户信息或运单编号。
- 同渠道、国家和地址类型匹配；如提供承运商、目的港，先精确匹配，批次不足时先放宽承运商再放宽目的港，不放宽已知国家和地址类型。界面明确显示实际范围；缺少国家或地址类型时提示可比性较低。
- 船名航次 + 目的港 + ATD日期近似识别批次；缺船名航次时使用柜号 + ATD日期。缺少这些信息的票仅计入票数，不作为独立批次；不能把几百票同船货当几百次独立运输。
- 每批次先取各段时效中位数，再计算批次P50、P90。票数包含可计算但未知批次的票，因此可能多于进入分位数计算的票。
- 展示近90天“实际含异常”、排除当前异常和历史单次异常超过7天的“正常参考”，以及相同匹配范围下近30天签收的实际含异常分布。预测采用实际含异常组，避免只展示正常快单。
- 当前所需的每段时效至少有5个可识别有效批次，才生成历史参考DW；不足时保留配置窗口。数据读取超过10000票也不生成参考窗口，避免截断后误算。
- 使用P50—P90向上取整为天数，至少保留全程1天、到港后0天，再按现有到港优先与较晚范围规则计算；Amazon仍只显示最晚预计送仓日所在的一周。
- 页面显示同渠道、已知国家及地址类型下近90天离港仍未签收的票数（排除本票，未进一步按承运商和目的港细分）。未完成慢单不进入已完成样本分位数，此数量仅提示偏差，尚未实现积压或生存分析校正。
- 历史参考不会自动覆盖配置、人工窗口、预计送仓字段或预警期限。点击“填入历史窗口”只填入表单并预览；核对保存后才成为该票的人工窗口。已保存的人工窗口不会因历史数据变化而漂移。
- 仍采用记录日期，未推断目的地时区。历史分布不是未来覆盖率或准确率承诺；下一阶段再增加预测快照、命中率回测和积压校正。
