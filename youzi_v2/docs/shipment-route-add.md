# 单票与批量新增 DPS 路由

港前、在途运单的操作列提供“新增路由”。批量操作时先勾选运单，再从表格下方选择“运单维护 → 新增路由”。单次 1—50 票，共用填写的时间与节点状态，描述中的派送仓库可逐票带入。

“时间设置”默认收起，并显示当前节点时间和预计派送时间。展开可调整日期和时分秒。节点时间默认打开弹窗时的当前时间，预计派送时间默认当前日期加 15 天。所有时间按本机输入的日期时间原样提交，不自动换算时区。

常用节点可包含入库、清关、离港、到港待卸船、中转仓、约仓、尾程交接及签收。点击快捷项会带入描述及数字状态，仍需“确认新增”后提交，可修改描述。

在“节点描述”输入关键词，会提示名称或描述中含有该关键词的可用快捷项，英文匹配不区分大小写。选择一项会带入完整描述和对应状态，也可继续手动填写。

## 状态与配置

在“后台管理 → 码表 → 运单明细状态”维护，对应 `shipment_route_status_codes`。`code` 是系统内部状态，`DPS status` 是发送给 DPS 的数字状态。新增路由支持已启用的码表项和「100 · 信息传递」。信息传递可保存为快捷语并发送到 DPS，轨迹中的 100 节点不会覆盖运单的关键明细状态。默认状态映射见 `db/shipment_route_status.py`。

根目录本地 `config/config.json` 中的 `dps_updateRoute` 对象配置 `url`、`method`（默认POST，支持PUT）及可选 `timeout`（秒，默认30，最大60）。授权复用根级 `dps_authorization`，也兼容块内鉴权。配置文件保持本地。

在“新增路由”弹窗右上角打开“路由配置”，可添加、修改或移除常用节点。每项填写按钮名称、明细状态和节点描述。保存后立即更新快捷按钮，保留当前运单表单，也不会向 DPS 提交节点。

关键节点按明细状态码表的顺序排列，同一状态下保留原有顺序。停用状态显示在配置列表的关键节点之后。「100 · 信息传递」排在状态下拉、配置列表和快捷按钮的最后。

带日期的描述可使用 `{预计交仓日期}`，已有模板里的独立 `N/N` 也可继续用。例如 `Expected to be delivered on {预计交仓日期}（预计交仓时间：{预计交仓日期}）`。选用后，从空白的“预计交仓日期”选择实际约好的日期，所有占位符会替换为 `MM/DD`，可在提交前预览。交仓日期与表单的“预计派送时间”分别填写。一次新增多票时，共用同一个交仓日期。

签收模板示例为 `Delivered to {派送仓库} on {完成派送日期} local time.（{派送仓库}当地时间{完成派送日期}-已完成派送）`。完成派送日期按目的地当地日期选择，显示为 `MM/DD`。提交按钮上方显示明细状态和最终描述，批量时直接按仓库显示描述与票数，可滚动查看。缺少派送仓库时，预览区列出对应运单号，可补齐运单仓库，或单独处理并在描述中填入实际仓库。实际派送日期不同的运单需分批提交。

快捷项保存到本地 `dps_updateRoute.presets`，每项包含 `label`、`status`（DPS 数字状态）和 `text`。旧配置中不可新增的状态可在配置页移除或改选，快捷按钮只展示可新增的状态。缺少 `presets` 时使用默认快捷项，配置空数组时不显示快捷项。

## API

- `GET /api/v1/shipment-routes/options`：返回可新增路由的状态 `statuses` 及供编辑的本地快捷项 `presets`。
- `PUT /api/v1/shipment-routes/presets`：保存常用节点列表，最多 100 项。只更新本地配置中的快捷项。
- `POST /api/v1/shipment-routes`：接收 `ids`、`nodeTime`、`estimatedDeliveryDate`、`nodeDesc`、`status`。未提供时间时，后端分别采用当前时间和当前时间加15天，格式为 `YYYY-MM-DD HH:mm:ss`。
- 逐票发送 `commerceWaybillId` 与其余四个DPS字段；最多四票并发，顺序返回逐票成功、失败或待核对及汇总。提交前检查全部运单ID和状态；写请求不自动重试。

## 结果核对

本次提交后表单锁定，防止部分成功时再次整批新增。超时、非正常响应视为结果待核对，需检查DPS路由后再决定是否重开提交。

成功后用现有明细状态同步接口回读成功运单，不直接把补录的历史节点设为最新状态；回读失败单独提示，不重复新增。完整内部轨迹可另用现有“更新内部轨迹”。无数据库迁移，更新后重启后端、刷新前端。

`python -B -m unittest youzi_v2.test_shipment_route_add -v` 使用模拟请求验证报文、默认时间、动态状态校验、批量部分失败和超时不重试；不向真实运单发送请求。
