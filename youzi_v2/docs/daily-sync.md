# 每日同步

在「计划任务 → DPS 运单同步 → 每日同步」粘贴新 Authorization，点击 **保存并开始每日同步**。可留空沿用已配置授权；输入框不回显旧凭据。按钮是唯一启动动作，编辑输入和保存普通计划任务开关不会启动此流程。

## 执行范围

依次执行提货中、已入仓、在途运单同步，再更新全部内部轨迹、承运商轨迹和明细状态。日期范围沿用页面日期控件；在途使用发运时间，提货中/已入仓使用下单时间。继续本轮时沿用原日期范围。

后三项沿用各自全量按钮资格：内部轨迹查询符合既有状态条件的运单，承运商主要查询转运中运单，明细状态查询具备 DPS 运单 ID 的运单。不是当前分页或筛选结果。内部全量同步仍增量合并轨迹，不使用指定运单更新的覆盖模式。

原单项按钮、三类“依次同步全部”及定时开关保留；同一后端进程中的关联同步互斥。每日任务运行时，其他手动关联同步会提示冲突，定时关联同步明确跳过本次检查，不代表成功执行。

## 验证、进度和继续

新授权先通过已配置在途查询做一条记录的只读探测：要求 HTTP 200、业务 code 200、rows 数组。授权无效、请求失败或响应不可识别时不启动、不覆盖旧授权；403 不直接认定为授权过期。保存配置失败不启动。授权保存成功但后台启动失败时，提示分开说明保存与启动结果。

任务由后台线程执行，请求立即返回任务 ID。切换/刷新页面不影响同一个后端进程中的任务；计划任务页和顶部任务中心可查看六步状态、结果及错误。各阶段统计是最近一次执行的结果；候选、已处理、待处理计数反映该轨迹阶段跨尝试累计进度。无轨迹、无变化、未匹配、失败分别展示；部分完成不显示整轮成功。

明确的 DPS HTTP 401 或业务 code 401 会暂停该流程，更新授权后点击 **保存并继续未完成同步**。承运商独立鉴权失败只影响相应查询，不冒充 DPS 授权失效。

继续时跳过已完成步骤。轨迹/明细阶段保留初始候选与已完成检查点，只补查失败和未处理记录，不改变全量合并语义。DPS 列表缺少稳定游标时，未完成的列表步骤重新查询并去重落库，不从旧页码盲目跳过。源接口报告总数大于实际返回数时，不标记该步骤成功。

未完成任务默认继续，不能静默用新一轮掩盖遗漏；任务中心也不允许删除可继续的每日记录。只有最近一轮可继续。源行已不存在或不再具备查询资格时，保留待处理并需要核对。若暂不修复，可明确确认“结束本轮并保留结果”，旧记录保持未完成/失败结论，之后可开始新一轮，不会被改写为全部成功。

## 部署与凭据

首版为 **单后端进程**，不要使用多 worker、多个实例或独立脚本同时运行同步。共享租约是进程内锁。多实例需额外的跨进程任务领取与锁，当前未提供。

重启后端自动创建 `daily_sync_runs`。任务及检查点存本地业务数据库，顶部摘要复用 `task_history`。进程退出或开发 reload 后，未结束任务在下次启动标为“已中断”，需要用户继续；不承诺服务重启后自动执行。升级前按现有数据库备份规范备份。

授权只保存到 gitignore 覆盖的 `config/config.json` 根级 `dps_authorization`，以同目录临时文件原子替换并保留其他键。它不是凭据保险库，仍需限制配置文件和备份的访问权限。API、任务历史和日志不保存完整授权；前端不将授权写入 URL 或浏览器持久存储。不要把实际授权发到聊天或提交 Git。

本功能只读取远端数据，不自动登录、不拦截浏览器、不向 DPS 修改业务信息；也不新增费用、账单或收款数据接口。

接口定义见 [api.md](api.md#每日同步-daily-sync)。验证使用模拟接口和临时配置，不替代用户环境中的真实 DPS 验证。

## 订单流转专用授权

计划任务页另有“保存并同步订单流转”，独立使用 `dps_ddlz_authorization`，不改变六步每日同步及其 `dps_authorization`。该入口只复用订单流转页当前订单列表“手动刷新”的全量拉取、状态变化及结束记录逻辑，不额外刷新其他名单，也不修改轮询开关。

粘贴新授权后点击按钮，使用新授权在内存中完成一次既有订单流转列表拉取，成功且分页完整后才原子保存专用授权并更新本地快照。不是先保存再用额外查询验证，也不重复拉取列表。授权留空沿用当前订单流转授权、不清空配置。失败保留旧配置和旧快照；若授权已保存但本地更新失败，界面明确提示可用原“手动刷新”重试。

订单流转保存刷新仍是与原手动刷新相同的请求式操作，不加入六步任务的进度/续跑，刷新结果展示新增、状态变化和结束数量。同一订单流转同步已有执行时，本次明确跳过且不保存授权。两类授权原子保存共用配置写锁，避免互相覆盖配置键；完整凭据不回传、不写任务记录或浏览器持久存储。
