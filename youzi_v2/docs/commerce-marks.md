# 港前运单标识管理

港前列表新增「标识」列，按 DPS `params.markVos[].name`、`params.markVos[].colour` 展示徽章，并兼容顶层 `markVos`。优先读取 params 内字段，明确空数组清空；两处均缺少该字段时保留本地快照。名称不在配置中也显示，使用内部 `name:` 键筛选，不把名称当成远端 ID。

## 后台码表维护

进入「后台管理 → 码表 → 港前运单标识」新增或修改：

- 标识 ID：DPS 真实标识 ID（作为编码，创建后不可修改）。
- 标识名称：必须与 `markVos.name` 一致，名称唯一。
- 徽章颜色：六位十六进制色值，可用取色器选择。
- 排序、启用状态：只有启用项可用于增加、移除和编辑；停用项已有快照仍显示和可筛选。

支持 Excel 模板与导入（标识ID、标识名称、颜色、排序、启用）。新增码表目录保存在本地数据库 `commerce_mark_codes`，不再在 JSON 文件维护目录。旧 `dps_commerce_waybill_mark.marks` 在首次读取目录或同步时一次性迁入，已有同 ID 或同名码表项优先，迁移完成后不再用旧 JSON 覆盖，避免删除后复现。

私密 `config/config.json` 仅保留可选 `dps_commerce_waybill_mark.url` 及鉴权，优先复用根级 `dps_authorization`。码表修改后重新打开标识管理或刷新筛选目录即可，无需再次重启；首次升级需重启后端创建表。更新运单后按码表名称匹配 ID；刚新增映射、尚未同步的名称键也可用配置 ID 筛选。

## 操作

勾选 1 至 200 票港前运单 → 标识管理。增加保留其他标识，移除只移除选中项，编辑用选中项替换全部，编辑时不选标识表示清空；操作均展示二次确认。远端请求为 POST，参数 `type=0/1/2`、`markIds`、`commerceWaybillIds`；使用本地保存的 DPS `waybillId`，不使用运单号或本地 ID。缺少 DPS ID 或包含非港前运单时整批拒绝。

仅远端确认成功后更新本地快照；网络超时不自动重试，需先核对远端结果。任务接入全局任务与持久历史，关联修改前标识、操作类型和所选 ID。标识配置及真实业务操作只保存在本地，不能提交实际配置、运单信息或凭据。

## 筛选及迁移

标识筛选支持多选，任意一个匹配即命中，影响当前列表和「导出运单」的数据范围。只在港前菜单展示操作及筛选。每票标识现保存在独立 `shipment_marks` 关联表；接口仍返回相同的标识字段。首次升级自动从旧 JSON 回填，已有标识不需要重新拉取。已有运单筛选、同步字段配置保持原语义，标识快照单独从 `markVos` 同步。

接口：

- `GET /api/v1/commerce-marks/options`：配置操作目录 `items`，及包含远端未知名称的筛选目录 `filterItems`。
- `POST /api/v1/commerce-marks`：`{ ids: [本地运单ID], markIds: [标识ID], type: 0 }`。
- 运单列表及导出支持重复查询参数 `commerceMarkIds`。

开发验证仅使用合成数据和模拟 DPS，不执行实际远端标识更新。


## 同步标识目录

在「后台管理 → 码表 → 港前运单标识」Tab 下方专属工具栏点击「同步标识」，其他码表不显示该按钮。读取私密配置 `dps_getMarks` 的 `url`、`method`（默认 GET，可选 POST），鉴权复用根级 `dps_authorization`，缺失时回退块内 Authorization。响应必须为成功 code 和 data 数组，每项提供 id、name、colour；不保存创建人、租户等无关信息。

按 ID 新增或更新名称与颜色，新项默认启用；已有项保留本地启用状态和排序。远端没有返回的本地项不删除、不停用。空数组不清空目录。名称冲突、重复 ID/名称、格式错误或请求失败时整批不写入；同步结果展示新增、更新、未变化数量，并进入全局任务和历史。同步只读取远端目录，不调用远端标识增删接口。接口为 `POST /api/v1/commerce-marks/sync`。


## 运单标识关联表迁移

`shipment_marks` 以 `(shipment_id, mark_key)` 唯一存储每票标识，包含可空的 `mark_id`、远端名称、远端颜色、展示顺序与快照写入时间。名称已匹配码表时写 ID；未匹配时保留名称/颜色，ID 为空，码表补齐后查询即可解析 ID。码表记录删除或停用不删除运单标识快照。

启动时执行一次性回填，版本标记为 `shipment_marks.relation_migrated_v1`。回填在保存点内完成，校验失败会回滚且不写完成标记；重复启动不会把旧 JSON 覆盖到新关联表，也不会恢复已经清空的标识。历史只存 ID 的记录尽量利用码表补齐显示信息，未匹配 ID 保留原值。

显示、详情、筛选、导出范围和批量操作均从关联表读取。筛选使用关联表索引，不再逐行解析 JSON；列表按本页 ID 批量加载标识。运单同步及标识操作在同一事务中更新主表时间和关联项，删除运单时清理关联行。内部仓库层仍接受旧的 JSON 输入字段以兼容同步调用，但只写入关联表，不写主表旧字段。

升级前按部署流程备份数据库。原 `shipments.commerce_mark_ids` 和 `shipments.commerce_marks` 列保留原样作为迁移档案，不再读写，也不在本次删除。若回退到旧代码，必须先从关联表重建这两列的最新快照，不能直接把档案当作当前数据。接口及前端显示格式不变。
