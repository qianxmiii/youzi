# 个人手机网页模块

本模块供本人在 iPhone 浏览器使用，通过获准的家庭或公司局域网访问本机服务；不是微信小程序，不依赖云部署。

## 开发边界

- 新模块独立放在 `youzi_v2/mobile/`，后续按需建立 `frontend/`、`backend/`、`scripts/`、`tests/`。
- 保留 `youzi_v2/frontend/` 现有电脑端，不将桌面页面整体改造成手机版。
- 复用现有数据层和业务服务，使用同一份业务数据库，不复制出第二套手机业务数据。
- 尽量隔离手机专用代码；公共配置、认证和服务入口需要改动时，明确影响范围并保持兼容。
- 不在导入或启动手机模块时额外启动一套定时同步任务。
- 配置密钥、数据库和日志不放在前端或公开静态目录；测试使用合成数据。
- 所有新增开发保持在 `youzi_v2/` 内。

## 首版与进度

首版：个人登录、运单搜索、轨迹详情、异常待办和个人跟进。

基础备份及恢复校验已完成；独立配置、个人账号与会话保护已建立，iPhone HTTPS 访问已获本人确认。手机查单读取业务数据，异常待办允许更新已有通知的已读及完成状态，原电脑端页面保持不变。

## 手机查单

登录后可查询运单列表，输入运单号、客户编号、货件号、关联单号、客户或转单号关键词；支持每页 20 条的分页列表、详情与内部/承运商轨迹。轨迹每次最多读取 30 条，可继续加载。按运单号倒序，详情显示本地更新时间；数据来自电脑端已有同步结果，不意味着实时承运商查询。

所有手机查单路由均要求登录，业务数据连接使用 SQLite `mode=ro` 与 `query_only`，不执行原 `Database` 初始化、迁移或 seed。返回字段采用显式白名单；不会通过手机返回成本、付款状态、供应商等完整内部记录。搜索、加载和返回不触发同步，业务库不会因手机查询而写入。认证库正常记录会话状态，与业务库分离。

退出、会话失效或重新检查账号时连接失败，会清空页面中的业务数据并取消在途请求；无业务数据 localStorage 缓存。请求超时可重试，详情通过页面 hash 支持手机返回操作。异常待办与跟进写入留待下一阶段。

## 启动与检查

在仓库根目录 PowerShell 执行（无需改变 PowerShell 执行策略）：

```powershell
.\youzi_v2\mobile\scripts\start-mobile.cmd --check
.\youzi_v2\mobile\scripts\start-mobile.cmd
```

默认启动后电脑访问 `http://127.0.0.1:3002/`；停止使用终端 Ctrl+C。默认只允许本机访问。已增加显式指定 IP 与证书的 HTTPS 模式，见 [iPhone 局域网 HTTPS 验收](docs/local-https.md)；证书信任与防火墙需单独确认。原桌面入口 `localhost:5173` 不变，原桌面系统鉴权不在本次改动范围内。

支持 `--port 3012` 指定其他端口。脚本从任意当前目录启动时，均以仓库根目录解析路径；优先使用根目录 `.venv`，否则使用 PATH 中的 Python。已有 PowerShell 启动脚本仅供本机执行策略允许时使用，不要求绕过系统策略。

模块配置环境变量（仅影响手机模块，不宣称原电脑端已支持这些变量）：

| 变量 | 默认值 / 含义 |
| --- | --- |
| `YOUZI_MOBILE_DB_PATH` | `youzi_v2/data/youzi_v2.db`；未设置时先尝试 `YOUZI_DB_PATH` |
| `YOUZI_MOBILE_CONFIG_PATH` | `config/config.json` |
| `YOUZI_MOBILE_PORT` | `3002`；命令行 `--port` 优先 |
| `YOUZI_MOBILE_AUTH_DB_PATH` | `youzi_v2/data/mobile/auth.db`，独立的账号与会话库，不得指向业务数据库或配置文件 |

相对路径统一按仓库根目录解析。默认使用电脑端原有数据库；不要随意指向备份或新建另一份手机数据库。文件缺失时检查失败，不自动创建空库。当前检查只验证文件存在、依赖可导入及端口可用，不读取业务记录、不修改数据库、不校验第三方接口凭证。

不加载原 `context`，不注册旧版业务路由，不启动同步任务，不挂载配置和数据目录。新手机接口 `/api/mobile/` 默认需要登录，仅健康检查、账号状态、首次初始化和登录入口例外。

## 个人账号

首次打开本机页面时自行设置账号（3–48 位字母、数字、下划线或连字符）和至少 12 个字符的密码。设置成功后再登录；无开放注册和默认账号密码。密码不要发送到聊天中。

- 密码只存 scrypt 哈希和随机盐；会话只在浏览器 HttpOnly、SameSite=Strict Cookie 中保存原始随机凭证，服务器保存其 SHA-256 哈希。
- 会话有效期 8 小时；退出登录撤销该会话，改密或本机重置撤销全部会话。
- 15 分钟内累计 5 次认证失败后限速；本工具只有一个账号，因此使用账号全局失败计数。
- 写请求验证同源 Origin（浏览器提供时）及自定义请求头；不开放跨域，不把 Cookie 或密码放进 localStorage。
- HTTP 仅用于当前回环地址联调，Cookie 此时不带 Secure。未来通过 HTTPS 访问时自动设置 Secure；未完成 HTTPS、证书及网络限制前，不开启局域网监听。
- 首次初始化只允许回环来源。无需头像、手机号、微信授权。

忘记密码时，在本机交互式终端运行（非 HTTP 恢复接口）：

```powershell
python -m youzi_v2.mobile.backend.reset_password
```

按提示输入两次新密码，不回显、不接受命令行密码参数。拥有本机文件权限的人可以操作认证库，因此 Windows 账号和文件访问权限仍需保护。

认证库也属于敏感运行数据，已被现有 `youzi_v2/data/` Git 忽略规则覆盖。现有业务备份命令只备份业务数据库，不包含认证库；认证库损坏或丢失时应停止手机服务并按恢复方案处理，不随意删除文件或覆盖业务库。

## 手机运单页面

登录后默认进入首页，底部“首页 / 运单 / 待办 / 我的”分别进入对应页面。运单列表默认显示在途，列表、详情分别显示，返回列表保留当前分类的搜索、状态、页码和滚动位置；这些状态只保存在当前页面内存中，退出登录会清空。

- 港前运单：已下单、提货中、已入仓、已取消；默认全部状态。卡片与详情显示收货仓、计费重，详情不显示物流轨迹区块。
- 在途运单：转运中、已签收；默认转运中，可切换已签收或全部状态。详情提供内部及承运商轨迹。
- 后端直接复用电脑端 `shipment_order_status` 的分类和筛选规则，兼容历史在途与签收状态码。搜索和分页始终限制在当前分类及状态内。
- 客户下拉选项来自当前分类的全部运单，不随状态、关键词或分页缩小；选择客户后按完整客户名精确筛选，与状态、搜索同时生效。选择“全部客户”清除客户条件，切换分类及返回详情各自保留选择，退出登录清空。

## 手机首页

首页参考移动工作台布局，使用浅蓝背景、顶部四项概览、异常待办、最近三条待处理提醒和快捷入口；概览为未签收、今日到港、今日轨迹签收和待跟进数量，均来自已有数据库。下方明细状态以三列紧凑卡片展示，支持“全部 / 今日”切换和手动刷新。全部模式沿用电脑端明细状态统计及未签收口径，展示 10 类关键状态及“无明细状态”；非关键 INFO 节点按无明细状态处理。

今日模式按电脑本机日期及各节点发生日期统计今日异常、离港、到港、内签收、到中转仓、快递交仓和轨迹签收，字段及范围与电脑端今日动态一致，不使用运单同步更新时间。同一运单可计入多个今日节点；内签收和轨迹签收分别统计，不代表相加后是不同运单数。

接口 `/api/mobile/home` 要求登录，使用只读连接与同一数据库快照，不触发同步。切换模式保留在当前页面内存，退出登录清空；切回首页或点击刷新重新统计。

## 异常跟进待办

底部“待办”显示电脑端已有的异常跟进通知，可按待处理、已完成、全部筛选，搜索运单号或客户并分页。查看运单后返回待办，保留筛选及页码。

“标为已读”保留待处理状态；“完成本次跟进”更新同一业务库中的通知完成状态，电脑端刷新后可见。完成提醒不会解除运单异常、修改运单或触发外部同步。重复提交幂等，缺失通知返回 404；写请求沿用登录、同源及请求体限制。

读取使用只读连接，通知状态更新使用 `mode=rw` 打开已有库，复用电脑端通知仓储；不建表、不迁移、不扫描生成提醒、不启动后台任务。当前仅接入异常跟进通知，未接入时效预警、货件组、报价或付款待办；空列表不表示其他类型待办为空。新提醒仍由电脑端现有扫描生成。

启用通知写入前已额外备份：`youzi_v2/data/backups/youzi_v2-20261018-163630-82ab4244.db`，完整性检查通过。自动测试仅修改临时合成数据库，真实库只做读取兼容检查。
